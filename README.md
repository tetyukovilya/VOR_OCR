# ВОР-автоматическое создание Ведомости объёмов работ из чертежей АР/КЖ

Инструмент для полуавтоматического формирования черновика **ВОР (ведомости
объёмов работ)** из PDF-листов рабочей документации разделов **АР**
(архитектурные решения) и **КЖ** (конструкции железобетонные).

Каждый лист парсится, из него достаются нужные таблицы (экспликация полов,
спецификация армирования, сводная ведомость расхода стали), к фактам
применяются расчётные правила из JSON-справочников, а результат выгружается
в Excel-файл, готовый для проверки инженером.

> Проект — рабочий прототип. Все результаты помечаются статусом
> «Черновой» / «Требует уточнения» и требуют проверки человеком —
> см. раздел [Ограничения и известные проблемы](#ограничения-и-известные-проблемы).

## Структура проекта

```
app/
├── extraction/
│   ├── ar.py            # извлечение фактов из листов АР (через OCR)
│   ├── kj.py             # извлечение фактов из листов КЖ (текстовый слой PDF есть)
│   ├── rules_ar.json      # справочник/настройки для АР (зона штампа, OCR, колонки таблиц)
│   └── rules_kj.json      # справочник расчётных правил для КЖ (бетон, сталь, сверка)
├── rules/
│   ├── engine_ar.py       # применение правил rules_ar.json к фактам ar.py → строки ВОР
│   └── engine_kj.py       # применение правил rules_kj.json к фактам kj.py → строки ВОР
└── export/
    ├── export_ar.py        # выгрузка ВОР по АР в .xlsx
    └── export_kj.py        # выгрузка ВОР по КЖ в .xlsx (+ лист «Журнал сверки»)
```

(Точное расположение `export_*.py` в дереве пакетов не зафиксировано — по
импортам видно, что `extraction/` и `rules/` лежат внутри пакета `app`;
`export_*.py` запускаются как самостоятельные скрипты и импортируют модули
через `app.extraction.*` / `app.rules.*`.)

### Разделение АР и КЖ

Разделы обрабатываются двумя независимыми, симметричными по архитектуре
конвейерами — общего кода почти нет, потому что исходные листы устроены
принципиально по-разному:

| | АР | КЖ |
|---|---|---|
| Текстовый слой в PDF | Отсутствует (шрифты переведены в кривые при экспорте из CAD) | Есть |
| Способ извлечения | Рендер в растр + Tesseract OCR + кластеризация слов по координатам | `pdfplumber` — векторные таблицы и слова напрямую из PDF |
| Ключевая таблица | «Экспликация полов» (фиксированная разметка колонок по чертежу-эталону) | «Спецификация к армированию сечений» + «Материалы», «Ведомость расхода стали» |
| Итог правил | Объёмы полов по видам покрытия, м² | Объёмы бетона, м³, и стали, т |

## Как это работает (конвейер)

* = ar или kj приписка файла для листов АР и КЖ

1. **Извлечение (`extraction/.py`)** — читает первую страницу PDF-листа,
   находит шифр листа в зоне штампа (по регулярке из `rules_*.json`),
   находит нужные таблицы и превращает их в датаклассы (`SpecRow`,
   `SteelSummary`, `ExtractedTable` и т. п.) со ссылкой на источник
   (`SourceRef`: файл, страница, bbox) для последующей проверки.
2. **Правила (`rules/engine_*.py`)** — берёт факты из шага 1 и
   JSON-справочник (`rules_ar.json` / `rules_kj.json`), сопоставляет
   позиции по ключевым словам, считает объёмы по коэффициентам и
   формирует строки `VorRow` (раздел / подраздел / наименование работы /
   ед. изм. / объём / формула расчёта / статус проверки / комментарий
   со ссылкой на источник).
   Для КЖ дополнительно выполняется **автоматическая сверка**
   (`cross_check_steel`): сумма масс позиций из «Спецификации» сравнивается
   с итогом «Всего» из «Ведомости расхода стали» — расхождение сверх
   допуска (`tolerance_kg`) помечается статусом «Требует уточнения».
3. **Экспорт (`export_*.py`)** — собирает `.xlsx` с форматированием
   (заливка по статусу проверки, перенос текста, закреплённая шапка) и,
   для КЖ, отдельным листом «Журнал сверки».

## Установка

```bash
pip install pdfplumber openpyxl pytesseract Pillow numpy
```

Для раздела **АР** дополнительно нужен сам Tesseract OCR (не Python-пакет,
отдельная программа) с русской языковой моделью:

```bash
# Linux
sudo apt install tesseract-ocr tesseract-ocr-rus

# Windows — установщик:
# https://github.com/UB-Mannheim/tesseract/wiki
```

Если `tesseract` не попал в `PATH`, путь до `tesseract.exe` нужно указать
явно в начале `ar.py`:

```python
pytesseract.pytesseract.tesseract_cmd = r"C:\Program Files\Tesseract-OCR\tesseract.exe"
```

Для раздела **КЖ** внешние зависимости, кроме Python-пакетов, не нужны —
текстовый слой в PDF уже есть.

## Использование

Каждый пайплайн можно запустить как отдельный скрипт.

**КЖ** (быстрее, точнее — текстовый слой в PDF):
```bash
python kj.py путь/к/листу_КЖ.pdf        # только извлечение фактов, вывод в консоль
python export_kj.py путь/к/листу_КЖ.pdf [путь/к/результату.xlsx]
```
Если путь к результату не указан, файл сохраняется как
`<папка_с_pdf>/output/ВОР_черновик_КЖ.xlsx`.

**АР** (требует установленный Tesseract с `rus`-моделью):
```bash
python ar.py путь/к/листу_АР.pdf         # только извлечение фактов, вывод в консоль
python export_ar.py путь/к/листу_АР.pdf [путь/к/результату.xlsx]
```

## Формат результата (ВОР)

Каждая строка выгрузки содержит:

`Раздел · Подраздел · Наименование работы · Ед. изм. · Объём · Шифр документа · № листа · Исходное проектное значение · Формула расчёта · Статус проверки · Комментарий`

Статус проверки — сигнал инженеру, а не гарантия качества:
- **Черновой** — извлечено и посчитано автоматически, замечаний нет;
- **Требует уточнения** — например, для стали, пока не пройдена сверка
  (`cross_check_steel`);
- **Проверено ГИП** — проставляется вручную после проверки.

Для КЖ дополнительно формируется лист **«Журнал сверки»** с итогами
сравнения суммы позиций спецификации и сводной ведомости стали, списком
учтённых позиций и (если расхождение вне допуска) текстовым пояснением
вероятной причины.

## Настройка под другую серию чертежей (`rules_*.json`)

Все параметры, специфичные для конкретного шаблона листов заказчика
(зона штампа, регулярка шифра листа, ключевые слова таблиц, коэффициенты
расчёта, границы колонок для фиксированной разметки АР), вынесены в JSON
и не требуют правки кода:

- `sheet_stamp_zone`, `sheet_code_regex` — где и как искать шифр листа;
- `rules_ar.json → floor_explication_table` — координаты границ колонок
  таблицы «Экспликация полов» (в долях ширины таблицы), подобраны под
  конкретный шаблон листа и **потребуют пересчёта** для другой раскладки;
- `rules_ar.json → ocr` — язык, DPI, порог уверенности и предобработка
  изображения для Tesseract; `min_confidence` намеренно занижен под мелкий
  текст шапок — при появлении мусора в результатах его стоит повысить;
- `rules_kj.json → concrete_rules / steel_rules` — ключевые слова для
  поиска позиций, коэффициенты пересчёта единиц, наименование работы,
  раздел/подраздел ВОР;
- `rules_kj.json → cross_check` — допуск сверки и позиции, исключаемые
  из суммы (например, «Уголок», не относящийся к арматуре).

## Ограничения и известные проблемы

- **АР-пайплайн в песочнице протестирован только с англ. моделью
  Tesseract** (без кириллицы) — на реальных листах нужна проверка с
  `rus+eng`.
- Жёстко прописанный путь к `tesseract.exe` в `ar.py` рассчитан на
  конкретную Windows-машину — при переносе на другую машину/ОС его нужно
  поменять или убрать, положившись на `PATH`.
- Разметка колонок «Экспликации полов» (`column_boundaries_ratio`)
  подобрана под один эталонный лист и не универсальна для всей серии.
- Известный кейс несовпадения сверки стали (лист `5235-1-9-КЖ2.1`):
  позиция «КР1» (плоский каркас) учтена в сводной ведомости, но её масса
  не детализирована в спецификации этого листа (есть только количество
  штук, ссылка на отдельный документ КР1) — требуется решение ГИПа,
  включать ли её в объём по этому листу.
- Оба пайплайна обрабатывают **только первую страницу** переданного PDF.
- Автоматический расчёт — черновой; отметка «Черновой» / «Требует
  уточнения» не заменяет проверку инженером перед использованием ВОР.
